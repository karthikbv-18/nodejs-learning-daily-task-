1. Error Handling
Error handling is used to handle errors without unexpectedly stopping the application.
try
Put code that may cause an error inside try.
try {
    console.log(name);
}

catch
If an error occurs in try, catch handles it.
try {
    console.log(name);
} catch (error) {
    console.log("Something went wrong");
}

Flow
try
 ↓
Error?
 ↓
YES → catch

finally
finally runs whether an error happens or not.
try {
    console.log("Running");
} catch (error) {
    console.log("Error");
} finally {
    console.log("Always runs");
}

Memory
try     → Try the code
catch   → Handle the error
finally → Always execute

throw
throw allows you to create an error yourself.
function checkAge(age) {

    if (age < 18) {
        throw new Error("Age must be 18 or above");
    }

    console.log("Allowed");
}

Handle it:
try {
    checkAge(15);
} catch (error) {
    console.log(error.message);
}

Output:
Age must be 18 or above

Memory
throw → create/raise an error

Definition
A module is a separate file containing code that can be reused by another file.

For example:

Flow

export
   ↓
app.js
   ↓

   ↓
use function

17. NestJS Controller
Definition
A Controller receives HTTP requests and decides which method should handle them.

Example:
import { Controller, Get } from "@nestjs/common";

@Controller("products")
export class ProductController {

    @Get()
    getProducts() {
        return ["Rice", "Sugar", "Oil"];
    }
}

Now:
GET /products

calls:
getProducts()

and returns:
["Rice", "Sugar", "Oil"]

18. Understanding the Decorators
@Controller("products")

means:
This controller handles routes beginning with /products.

And:
@Get()

means:
When a GET request comes to this route, execute this method.

So:
GET /products
      ↓
ProductController
      ↓
getProducts()
      ↓
Response

For POST:
@Post()
createProduct() {
    return "Product created";
}

This handles:
POST /products
